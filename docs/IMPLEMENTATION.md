# 구현 상세

## 시험 결과와 결시 상태 관리

시험 통계 화면에서 시험 정보, 검색 결과 건수, 응시자 목록을 한 번에 반환하도록 구성했습니다. 결시 확정 후 오입력을 복구할 수 있도록 확정과 취소 기능을 분리했습니다.

```text
검색 조건 확인
  → 전체 건수 조회
  → 시험 기본정보 조회
  → 응시자 통계 목록 조회
  → 화면 또는 엑셀 결과 생성
```

화면과 엑셀 생성에 같은 검색 조건을 사용해 조회 결과의 수치가 달라지지 않도록 했습니다.

## 검토계획과 대상 문항 저장

검토계획을 변경할 때 계획 정보뿐 아니라 분야별 문항 수, 문항 유형, 실제 검토 대상 문항이 함께 바뀝니다.

```text
계획 존재 확인
  → 분야와 필요 문항 수 검증
  → 분야 중복 확인
  → 문항 ID 중복 확인
  → 기존 구성 교체
```

검증 도중 실패하면 기존 구성은 변경하지 않습니다. 이 흐름을 [ReviewPlanService](../samples/exam-workflow/src/main/java/com/portfolio/exam/review/ReviewPlanService.java)로 재작성했습니다.

## 선정위원 자동 배정

분야별 위원과 문항을 조회한 뒤 문항을 위원에게 순차적으로 배정했습니다. 한 위원에게 문항이 몰리지 않도록 현재 배정 수가 가장 적은 위원을 우선 선택하고, 동일 문항의 중복 배정을 차단했습니다.

[ReviewerAssignmentService](../samples/exam-workflow/src/main/java/com/portfolio/exam/assignment/ReviewerAssignmentService.java)에서 다음 조건을 확인할 수 있습니다.

- 위원과 문항 ID의 공백·중복 검사
- 기존 배정 건수 반영
- 최소 배정 위원 우선 선택
- 이미 배정된 문항 제외
- 불변 목록으로 결과 반환

## 공개 코드 작성 기준

- 원본 소스의 클래스명, 메서드명, 쿼리를 복사하지 않았습니다.
- 고객사명, 테이블명, 운영 코드값을 일반 용어로 변경했습니다.
- 업무 흐름만 유지하고 Java 17 도메인 코드로 새로 작성했습니다.
- 정상 처리와 예외 조건을 단위 테스트로 확인합니다.
