# 설계하면서 확인한 점

## 시험 상태를 화면 값으로만 판단하지 않기

시험은 예정, 진행, 종료 상태가 순서대로 바뀝니다. 화면에서 버튼을 숨기는 것만으로는 잘못된 요청을 막을 수 없으므로 서비스 계층에서도 현재 상태와 시험 시간을 확인해야 합니다.

답안 제출 역시 시험이 진행 중일 때만 허용하고, 종료 후 요청은 저장하지 않는 방식으로 업무 규칙을 분리했습니다.

## 배정 작업의 정합성

수험번호와 좌석 배정은 일부 데이터만 반영되면 운영 과정에서 복구하기 어렵습니다. 배정 전에 시험장 정원, 기존 배정 여부, 대상자 수를 확인하고 같은 작업의 재실행 가능성도 고려해야 합니다.

대량 배정은 다음 순서가 명확해야 합니다.

1. 배정 대상과 제외 대상 확정
2. 시험장별 수용 인원 확인
3. 수험번호와 좌석번호 생성
4. 배정 결과 검증
5. 운영 자료 생성

## 통계 쿼리와 업무 조회의 분리

시험 결과나 부정행위 통계는 여러 조건과 집계가 필요합니다. 일반 목록 조회와 같은 쿼리에 집계를 계속 추가하면 화면 응답이 느려지고 변경 영향도 커집니다.

통계 전용 조회 모델과 Mapper를 분리하고, 화면과 엑셀 생성에서 동일한 조회 조건을 사용하도록 구성했습니다.

## 문항 생명주기 관리

문항은 출제 중, 검토 중, 선정 완료처럼 단계에 따라 허용되는 작업이 다릅니다. 현재 단계 확인 없이 수정과 삭제를 허용하면 검토가 끝난 문항이 바뀌거나 실제 시험과 연결된 문항이 삭제될 수 있습니다.

상태 변경은 가능한 이전 상태를 확인한 후 처리하고, 사용 이력이 있는 문항은 이력을 유지하는 방향으로 관리했습니다.

## 지금 다시 만든다면

- 시험과 문항 상태 전이를 명시적인 도메인 모델로 관리합니다.
- 대량 배정 작업에 작업 ID를 부여해 중복 실행을 방지합니다.
- 통계 조회를 별도 읽기 모델로 분리하고 실행 계획을 자동 점검합니다.
- 상태 변경과 관리자 작업을 감사 로그로 남깁니다.
- 주요 업무 규칙을 데이터베이스가 포함된 통합 테스트로 검증합니다.
