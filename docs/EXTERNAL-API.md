# 온라인 평가·오답노트 외부 API

온라인 평가 화면과 고객사 홈페이지를 연결하기 위해 인증, 시험 조회, 응시 화면, 성적, 오답노트 API를 설계하고 구현했습니다.

보관된 최종 인터페이스 정의서 V1.2에서 확인되는 계약은 제공 API 21개와 연계 요청 2개입니다. 개발 과정에서는 화면 연결용 API와 내부 호출까지 포함해 약 30개를 작업했지만, 이 문서에는 산출물로 확인되는 23개 계약만 적었습니다.

## 담당 범위

| 영역 | 주요 기능 |
|---|---|
| 인증 | 사용자 정보 검증, 인증 토큰 생성, 회원 여부 확인 |
| 모의평가 | 목록, 응시 화면, 이력, 채점지, 성적표, 전체·오답 다시 풀기 |
| 자율평가 | 분류 조회, 응시 화면, 이력 조회 |
| 오답노트 | 목록·분류, 즐겨찾기, 휴지통 이동·복원, 초기화 |
| 오답 다시 풀기 | 출제 범위, 시험 생성, 이력 조회·삭제 |
| 홈페이지 연계 | 과정 목록과 회원 확인 요청 |

## 구현 방식

인증 토큰을 먼저 확인하고 토큰의 사용자와 요청 사용자가 일치하는지 검증했습니다. 시험 목록은 과정과 공개 기간을 기준으로 제한했고, 응시·성적 화면은 조회 API가 반환한 식별자를 그대로 신뢰하지 않고 소유권을 다시 확인했습니다.

오답노트는 하나의 삭제 플래그로 모든 상태를 처리하지 않았습니다. 기본 목록, 즐겨찾기, 휴지통 상태를 명시적으로 전환하고, 여러 문항을 한 번에 처리할 때는 전체 검증이 끝난 뒤 저장하도록 구성했습니다.

```text
요청 → 토큰 검증 → 사용자/과정 권한 확인 → 업무 규칙 적용 → 표준 응답
                                              └ 실패 시 업무 오류 코드
```

## 공개 예제

[ExternalAssessmentService](../samples/exam-workflow/src/main/java/com/portfolio/exam/api/ExternalAssessmentService.java)는 다음 규칙을 재작성한 예제입니다.

- 토큰의 사용자와 요청 사용자의 불일치 차단
- 응시 가능한 시험만 반환
- 오답노트 상태 전이 검증
- 요청 ID를 이용한 중복 변경 방지

실제 URL, 토큰 형식, 고객사 코드, 원본 DTO와 쿼리는 포함하지 않았습니다.
